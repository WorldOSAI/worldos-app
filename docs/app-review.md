# App review native capability

`@capawesome/capacitor-app-review` is pinned to 8.1.0 for Capacitor 8. It supplies
`AppReview.requestReview()` on iOS and Android. System UI display and review submission
are not observable success signals.

The app-local `AppReviewContext` plugin provides `getContext()`:

- `installationId`: a randomly generated app-scoped UUID, persisted in native preferences.
- `sessionId`: a process-lifetime UUID, shared across activity/WebView recreation and reload.
- `active`: whether the app is currently active (Android also requires window focus).
- `appVersion`, `osVersion`: diagnostic context for user feedback.

Android requires a visible installed Play Store package; unavailable devices reject context
lookups. There is no advertising ID, device fingerprint, signing secret or extra runtime
permission. iOS registers the plugin instance in the existing bridge controller; Android
registers its plugin before `BridgeActivity.onCreate`.

WorldSims owns all presentation, star routing, account/device quotas, feedback delivery and
analytics. It requires both plugins before displaying an invitation. Ship this native build
before enabling `APP_REVIEW_ENABLED=1` in WorldSims. Older binaries continue normally.

From a clean installation:

```sh
npm ci
npm run mobile:sync:release
```

Capacitor-generated Android/SPM dependency files are regenerated by sync; do not commit
those generated diffs. Production sync must use exactly `https://worldos.cc`.

Acceptance: verify identical session IDs across reload/background/account switches and
activity recreation, a new session ID after process restart, and a stable installation ID
across upgrades. On each store's supported test distribution, choose 5 stars and verify the
native request; 1–4 stars must not call the store. Actual review submission requires a person
and is not inferred from the plugin promise.
